# pulse-backend — инструкции агенту

Актуализировано 19.10.2026. Операционный HTTP API — Go ≥1.25, Gin 1.12, pgx/Squirrel и gRPC SDK pulse-contracts. Структура: cmd, internal, api, configs, build/package, deployments, docs, test. Перед изменением читай [CONTRIBUTING](CONTRIBUTING.md), [архитектуру](docs/architecture.md); запуск/настройки — [README](README.md). Статус приложения/целей — [handbook](docs/project-handbook/chapters/02-status.md); audit и execution log в docs сохраняют связь требований/проверок.

## Границы и совместимость

HTTP Gin → service → domain; конкретные зависимости собираются bootstrap. SQL только в repository/postgres, protobuf только в adapter/grpcml. map[string]any — для расширяемого JSON/внешней адаптации; сущности/DTO типизированы. SQL строится Squirrel с параметрами, без конкатенации значений. Публичный SDK и proto принадлежат contracts; reflection/JSON-кодеки вместо generated типов не добавляются.

Сохраняй /api/v1, PostgreSQL схему, Excel, nullable/int64/false/нули; `domain.Field[T]` различает отсутствие и null в PATCH. Ярус приходит из ML: последний низкий риск и data_ok=false его не отменяют. Прогоны резервирует PostgreSQL lock, тревоги/завершение пишутся атомарно, статусы переносятся по unitek_id. ID Pulse отличается от внешних ID; архив, active, review и права независимы. Миграции запускаются явно; рабочая БД не используется как TEST_DATABASE_URL.

## Реализация и проверки

Гоформатирование, группы импортов std/external/local, context первым аргументом, slog, ошибки с причиной. `make check`, `TEST_DATABASE_URL=... make integration`, `make build`; integration использует отдельную тестовую БД/временные схемы. `make fmt` меняет файлы и запускается в пределах своего diff. Стиль и архитектурные тесты — CONTRIBUTING/test/architecture.

Local/legacy являются разными профилями; подтверждённый local RBAC в коде не означает включённый personal login в текущем Compose. Секреты/profiles не меняются ради документации; bootstrap и cookie/origin применяются по инструкции. Обучение выполняется в model, backend его не устанавливает.

## Данные и корректность ML

- Маркеры 9999/999.9 очищаются по конкретному каналу до агрегации; валидные нули частоты, тока и дебита сохраняются. Уставки `is_set=true` / `set_*` отделяются от измерений. Alias с регистровым префиксом и русское displayname канонизируются до применения правил; схемы принадлежат `pulse-model/esp/params`.
- Для обучения/оценки обязательны temporal split (train раньше test), group по физическому месторождению, purge/embargo и причинный контекст. Нормировщик fit только на train, калибратор на calibration, порог на selection; novelty учится на нормальных окнах вне предотказного интервала. SMOTE сырых окон запрещён. НГДУ в имеющемся бейзлайне — явное ограничение, а не доказанный oilfield split.
- Классы #2/#8/#9 на старте — суперкласс отложений/механического засорения. Алерт объясним; риск, накопленный ярус, качество данных и решение технолога независимы. Горизонт 7–14 суток — цель, historical group-CV и генератор не служат временной приёмкой. Model не зависит от Data; truth сценария не подмешивается во вход модели.

## Порядок работы

Команды выполняются из корня этого checkout. [README](README.md) — локальная точка входа; соседние pulse-репозитории нужны только для соответствующей интеграции. В общем workspace сохраняй существующие ссылки data/.venv и чужие изменения. Для командной работы используй `.codex/TEAM.md` родительского workspace, если он доступен; standalone checkout от него не зависит.

Новая фаза: краткий план → одобрение пользователя → изменения и проверки → DoD; уже данное одобрение учитывается. Отчёт содержит файлы, проверки/результаты, допустимые SKIP и открытые вопросы. Секреты, живые данные и веса в Git не включаются. Исторические исходники вне этого checkout не изменяются.
