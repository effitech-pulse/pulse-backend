# O2 — локальная наблюдаемость: архитектура и handoff

Статус: **IMPLEMENTED / LOCAL RUNTIME VERIFIED; итог Senior и публикации — в execution ledger**. Основание: [требования TL](o2-q0-execution-2026-10-20.md), [принятый O1](observability-o1.md), [roadmap O2/O-data](functional-roadmap-2026-10-20.md). Продолжение одобрено пользователем; численные пределы ниже — выбранные защитные настройки синтетического пилота, не измеренная производственная ёмкость. Q0 проектируется отдельно; O2 исполняется и принимается первым. Дизайн не меняет API/proto/БД, idempotency, scope, deadline или модель.

Редактируемый C4: [o2-observability.drawio](o2-observability.drawio), отдельные страницы Current Context, Optional Context, Current Containers, Optional Containers и Processor Component. Стрелки telemetry не являются бизнес-событиями или durable jobs.

## Существующий путь и принятое решение

Проверены исходные seams: `internal/observability/{tracing,logging,context}.go`, `cmd/api/main.go`; ML `pulse_ml/{observability,server}.py`; Data `utils/telemetry_emulator/{observability,server}.py`; frontend `nginx.conf`; существующие `deployments/compose.{prep,o1-f1}.yaml`. Backend HTTP→PostgreSQL→ML и отдельный collection→Data/source→PostgreSQL уже инструментированы O1. Вычислительное ядро pulse-model и SDK pulse-contracts — библиотеки, не новые сетевые контейнеры. Landing не участвует. Историю O1/F1 не пересматриваем.

Выбор: **один Collector-contrib; traces/metrics через OTLP/gRPC; один централизованный маршрут logs через filelog для всех четырёх производителей; Loki OTLP/HTTP, Tempo OTLP/gRPC, Prometheus scrape, Grafana UI**. Stdout продолжает получать O1 JSON и сохраняет Docker local rotation; Collector stdout не читает. Ни Docker.sock, ни Docker log directory, ни глобальные host globs не монтируются. Optional-профиль выключен по умолчанию.

Безопасный formatter остаётся deep module: optional file adapter получает только окончательные очищенные JSON bytes. Его deletion test: удаление adapter возвращает нынешний stdout, без переноса фильтров в callers. Locality sanitization остаётся в O1 module; exporter adapter не форматирует произвольные error/message/LogRecord. Публичный SDK/proto не расширяется.

Рассмотренные альтернативы:

| Вариант | Решение |
|---|---|
| Go/Python SDK log bridges + Nginx syslog | Не вводим: совместимый Go log SDK0.14 имеет [busy-spin при backpressure](https://github.com/open-telemetry/opentelemetry-go/security/advisories/GHSA-hjf4-fphr-2h65). Raw root logging bridge также обошёл бы O1 allowlist. |
| Общий syslog | [Nginx поддерживает UDP/Unix socket](https://nginx.org/en/docs/syslog.html), не следует предполагать TCP/retries. Меньше файлов, но потери до receiver не имеют точного счётчика. Оставлен альтернативой при провале file-I/O проверки; одновременно не включать. |
| Только Collector+Jaeger | Более узкий trace pilot не закрывает выбранный TL результат общего просмотра трёх сигналов. Одновременно Tempo/Jaeger не ставим. |

### Startup-only конфигурация, privacy и trust

Только `PULSE_OBSERVABILITY_ENABLED=false|true` включает exporters/file adapter; пустое/false не создаёт сетевых клиентов/очередей/файлов. Internal endpoint фиксирован `otel-collector:4317`; arbitrary endpoints/userinfo/query/headers не поддерживаются пилотом. `PULSE_OBSERVABILITY_LOG_DIR=/var/log/pulse` разрешён только в optional container profile. Ошибка необязательной telemetry-конфигурации отключает её с static diagnostic; O1 stdout и бизнес-приложение запускаются. При выключенном профиле ни SDK, ни exporter не могут включиться через `OTEL_*`.

Сохранить O1 resource allowlist и startup-only env workaround; расширить один изолирующий scope на construction **всех trace+metric providers/exporters**, затем восстановить присутствие/значение env в defer/finally до запуска application jobs/listeners и собственных queue workers. Удаляем из видимости конструктора существующие `OTEL_RESOURCE_ATTRIBUTES`, `OTEL_SERVICE_NAME`, ключи с префиксом `OTEL_EXPORTER_OTLP_`, `OTEL_PYTHON_EXPORTER_OTLP_GRPC_`; не читаем произвольные env detectors. Python startup rollback exception: после валидации enabled config допускается заранее резервировать один inert lifecycle daemon, который только ждёт Event и не читает env/не экспортирует/не логирует до окончания restoration. Он становится тем же snapshot/lifecycle owner, а не дополнительным/replacement worker. Failure reserve → zero optional acquisitions + O1; failure дальнейшего construction/start → cleanup тем же owner после выхода из env scope, caller bounded. Queue workers по-прежнему запускаются после restoration; disabled path не резервирует поток. Library-created channel/reader threads требуют отдельной проверки конструктора: не заявляем блокировку любых чужих env readers. Explicit endpoint, empty headers, insecure internal transport, no compression,500ms timeout и Go retry disabled задаются также явно. Python retries ограничены общим500ms deadline, не очередью новой попытки.

Причина: [Python1.38](https://raw.githubusercontent.com/open-telemetry/opentelemetry-python/v1.38.0/exporter/opentelemetry-exporter-otlp-proto-grpc/src/opentelemetry/exporter/otlp/proto/grpc/exporter.py) использует `headers or environ...`, поэтому `{}` не отключает env headers; [Go options](https://raw.githubusercontent.com/open-telemetry/opentelemetry-go/v1.38.0/exporters/otlp/otlptrace/otlptracegrpc/internal/otlpconfig/options.go) применяют env до overrides и могут прочитать credential file. Internal OTel Info diagnostics оставить выключенными, ErrorHandler не вызывает `Error()/repr()`; [endpoint-info advisory](https://github.com/open-telemetry/opentelemetry-go/security/advisories/GHSA-8wmf-6v46-5gfg) включает1.38. Избегаем SDK OTLP/HTTP из-за [unbounded-response advisory](https://github.com/open-telemetry/opentelemetry-go/security/advisories/GHSA-w8rr-5gcm-pp58). grpc-go1.78 входит в [официальный advisory range](https://github.com/grpc/grpc-go/security/advisories/GHSA-hrxh-6v49-42gf): backend здесь client, xDS/server не добавляем; внешнее размещение требует отдельного applicability review, O2 не выдаёт baseline за vulnerability-free.

Нельзя повторно создавать providers после старта. Mutex защищает собственные constructors, не чужие process-global env readers. Test canary включает poisoned generic/signal endpoint/headers/certificate/provider, отсутствие/пустые/непустые значения, exact restoration, отсутствие чтения poison file/дополнительного metadata и resource только из O1 allowlist. Baggage/tracestate не передаются; sampling100% локальный, public sampled flag не выбирает бюджет. Существующие error/span limits/Upload lifetime/root links остаются.

## Внутренний interface и видимые потери

Новые helpers приватные, рядом с observability, не новый общий пакет контрактов:

- Go: `type ExportConfig struct { Enabled bool; LogDir string }`; `NewRuntime(ctx context.Context, version string, cfg ExportConfig) (*Runtime, error)`; `(*Runtime).Shutdown(ctx context.Context) error`. `Runtime` владеет trace provider, meter provider, counting processor и file adapter. Существующий `NewProvider(version)` сохраняется для O1 tests/disabled path; общий startup helper не должен повторно захватить mutex. `cmd/api` создаёт runtime до bootstrap/scheduler/listener и завершает после прежнего business shutdown. `NewLogger(w,version)`/`Install(version)` сохраняются; internal constructor может принять только `func([]byte) bool` готового safe JSON для optional adapter.
- Python: frozen `ExportConfig(enabled: bool=False, log_dir: Path|None=None)`; `Observer(..., export_config: ExportConfig|None=None)` сохраняет старые аргументы provider/sink; `Observer.shutdown(timeout_millis: int=2000) -> None`. Runtime/export helpers в отдельном local `observability_export.py`; только запуск Observer меняет server bootstrap. `configure_logging` остаётся единственным safe root handler.
- File adapter: `try_emit(encoded: bytes) -> bool`, queue256 records, каждый≤8192 bytes; один worker. Очередь полной/закрытой→drop-newest и atomic counter, без format/log recursion. Ошибка write/rotate/panic→drop+counter и продолжение следующей записи; stdout попытка независима от file результата. Никогда не enqueue исходный slog/LogRecord/Exception.
- Trace adapter реализует публичный SDK `SpanProcessor`, использует официальный `SpanExporter` и **собственную единственную bounded queue256, batch≤64, flush≤1s, exporter deadline500ms**, один worker, без thread/goroutine на batch. OnEnd делает только bounded metric update + nonblocking enqueue; sampled spans only. Full→drop-newest+exact counter. Export failure/exception/panic→счётчик batches и records, batch discarded, без повторной прикладной очереди. Статус exporter не меняет Span status/business error.
- `ForceFlush` ждёт watermark записей, принятых до вызова, до переданного deadline; не блокирует OnEnd. Shutdown перестаёт принимать, очищает/учитывает pending при timeout и возвращается≤2s wall clock. Не cooperative fake exporter может оставить **один** worker заблокированным до завершения процесса; не создаём замену/новые worker, не заявляем отмену чужого кода. Python worker daemon; Go goroutine не удерживает возврат shutdown. Не запускаем potentially-blocking exporter.shutdown на вызывающем потоке. Это проверяется fake exporter, игнорирующим deadline.

Причина counting adapter: [Python BSP1.38](https://raw.githubusercontent.com/open-telemetry/opentelemetry-python/v1.38.0/opentelemetry-sdk/src/opentelemetry/sdk/_shared_internal/__init__.py) молча вытесняет deque и имеет TODO по force_flush timeout. [Go BSP1.38](https://raw.githubusercontent.com/open-telemetry/opentelemetry-go/v1.38.0/sdk/trace/batch_span_processor.go) имеет experimental self-observability. Не читаем private queue internals и не включаем global experimental mode ради обязательного AC. Minimal adapter даёт одинаковый наблюдаемый interface в обоих языках.

Aggregate counters/gauges хранятся в фиксированном наборе atomic/locked чисел, не очереди событий. Exporter errors не форматируются. Раз в10s safe static `telemetry.snapshot` выводит nonnegative integer поля `trace_queue_size`, `log_queue_size`, `trace_dropped_total`, `log_dropped_total`, `trace_export_failed_total`, `metric_export_failed_total` в stdout (и обычный file stream), с WARN при приросте потерь; событие не создаёт span. Только это новое имя и эти шесть числовых keys добавляются в O1 formatter/Collector allowlist. Optional try_emit выполняется до попытки stdout; file failure не отменяет stdout, но прежняя OS-блокировка stdout остаётся возможной. Сообщения SDK сами проходят нынешний O1 suppression. Crash до snapshot может скрыть последние counters; потери до Collector ack и после process kill не вычисляются точно. Lossless/durable/HA не заявляются.

## Filelog: пути, rotation и права

Три app adapters и Nginx пишут по одному stream:

| Producer | Source в producer | Collector read-only source |
|---|---|---|
| backend | `/var/log/pulse/pulse.jsonl`, `.1`, `.2` | `/var/log/pulse/backend/` |
| ml | тот же basename, отдельный volume | `/var/log/pulse/ml/` |
| data | тот же basename, отдельный volume | `/var/log/pulse/data/` |
| frontend | `/var/log/pulse/pulse.jsonl`, `.1`, `.2`; второй `access_log` в optional config | `/var/log/pulse/frontend/` |

Каждый `o2-logs-{producer}` — отдельный named local-driver **tmpfs,size=16m,uid=0,gid=20000,mode=2770**; producer RW, Collector RO. Это Linux Docker local-driver capability, которую проверяем на Desktop до enable; при отсутствии поддержки gate FAIL, не silent bind mount. Collector runs uid10001/gid20000; backend distroless uid65532 получает supplementary gid20000. Python остаётся текущим UID; файл0640, umask0027, setgid directory наследует group20000. Frontend build добавляет group telemetry20000 и nginx в supplementary group; UID nginx проверяется, не зашивается101. Collector не может открыть raw inputs/models/DB volumes; producer не монтирует чужой log volume.

Go/Python single worker выполняет rename/create rotation **до append**, если запись превысит2MiB: current→.1→.2, oldest unlink. Никакого copytruncate. Не более трёх файлов и одной записи в операции; это ограничение managed files, а не total filesystem usage. Tmpfs16MiB — отдельный hard filesystem ceiling; unlinked/open reader inode и checkpoint overhead требуют измерения. Collector offset checkpoint — отдельный RW `o2-filelog-offsets` tmpfs16MiB; restart поведения и потеря offsets проверяются, lossless recovery не обещается.

Nginx не имеет встроенной size rotation: optional `nginx.o2.conf` оставляет тот же safe format и `/dev/stdout`, добавляет только fixed file access_log, без URI/errors/native streams. Один `/docker-entrypoint.d/99-o2-logrotate.sh` при флагеtrue запускает один poll worker1s: size≥2MiB→rename/create0640→USR1 действующему master из фиксированного pidfile. При false script ничего не запускает. Dockerfile копирует только infra helper/config, без UI изменений. Проверить reopen/worker group/termination. Overshoot между poll зависит от нагрузки и **не объявляется2MiB hard cap**; предельный tmpfs обеспечивает16MiB, ENOSPC виден probe/canary и safe diagnostic. При failure не перехватывать native error log: O1 `error_log /dev/null crit` остаётся.

Collector filelog: четыре явных списка `{pulse.jsonl,pulse.jsonl.1,pulse.jsonl.2}` под названными directories; include_file_name/path/owner=false, max_concurrent_files12, max_log_size8192, oversized/malformed record целиком discard. Offset storage включён; start_at=beginning; receiver bounded retry max_elapsed_time5s, не infinite. Не добавлять `delete_after_read`, host attributes или parse-error body echo. [Filelog contract](https://raw.githubusercontent.com/open-telemetry/opentelemetry-collector-contrib/v0.163.0/receiver/filelogreceiver/README.md) объясняет rotation/offsets и возможные downstream losses.

Parser принимает только O1 schema: timestamp UTC, severity/event/resource и разрешённые поля; service.name должен соответствовать source directory. Reconstruct safe JSON body и OTLP fields из allowlist; удалить неизвестные attrs и исходный raw body. Trace32hex/span16hex становятся нативным LogRecord context только после проверки; request ID остаётся field. Nginx `duration_s` — секунды, app `duration_ms` — миллисекунды. Неполный/переполненный JSON не экспортируется как строка. Все правила проверяются на pinned Collector, включая canary nested/extra secret. Converter синтаксис фиксирует исполнитель после `validate`, schema значения здесь обязательны.

## Metrics и stores

Метрики — operational, ни model metadata, ни model quality. Без model/user/well/job/request/trace IDs, включая exemplars: SDK exemplar filter явно AlwaysOff через публичный interface, ambient OTEL_METRICS_EXEMPLAR_FILTER не выбирает другой режим. Связь логов с trace сохраняется отдельно. Новая отдельная planning-задача отчётов/активности сотрудников/AI-навигации не добавляет сюда browser RUM, clicks или employee identities. Сервисная метка `service` — одна из четырёх static names; `layer` — http/rpc/db/source/operation; `operation` — allowlisted route template/RPC/static span name, unknown→other; `outcome` — ok/error. Не принимать raw path, source URL, error string или свободный status. Histogram attrs только service/layer/operation/outcome. Максимум64 operation values на процесс, unknown объединяются; общий cardinality guard128 attribute sets на инструмент с overflow→other и counter. Resource не конвертируется автоматически в metric labels. В Collector **только metric pipeline** удаляет service.instance.id/service.version до Prometheus translation/target_info; иначе translator может добавить их через служебные labels даже при resource_to_telemetry_conversion=false. Traces/logs сохраняют разрешённые resource fields. Проверить фактическую exposition и все label sets, включая job/instance/target_info; scrape instance допустим только статический Collector endpoint, не app random ID.
