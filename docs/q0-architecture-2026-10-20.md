## Решение

Принятый source добавил bounded file reader и compact saved-file normalization → bounded canonical CSV → strict Python UploadPinned, сохранив старый sync путь. Shared scalar semantics переиспользуются; legacy MapTelemetryAt/telemetryCSV интерфейсы сохранены, а bulk Measurement maps в saved path удалены принятой memory correction. Q0 вводит bounded raw+canonical snapshot в PostgreSQL, явную типизированную ожидаемую identity и отдельный строгий UploadPinned. В Q1 этот snapshot записывается одной транзакцией с job/outbox. Q0 proof доказывает повторное чтение после рестарта, но не является долговечным worker или очередью.

До первого построения признаков ML разрешает ожидаемый digest в локальном immutable registry, проверяет файлы, runtime/recipe и реальное decision_rule(context, "upload"); при несовпадении отказывает. Нет fallback на ML_MODEL_NAME/latest. Реальные частные файлы остаются за отдельным policy gate; synthetic proof разрешён сейчас.

## Модуль и интерфейс Q0

**Stored file check** — глубокий module: bounds, normalization, identity, storage и replay сосредоточены за небольшим interface; caller не собирает hashes или actor вручную. Seam существующего `TelemetryScorer.Upload` оставляем для legacy. Новый seam `PinnedTelemetryScorer.UploadPinned` передаёт ожидаемую identity и canonical bytes; adapter gRPC — один production adapter, тестовый in-process gRPC server — второй реальный способ проверки transport seam. Не вводим общий plugin/storage platform: PostgreSQL — единственный выбранный production adapter. Deletion test: удаление Stored file check вернёт квоты, hashing, scope и immutable replay в HTTP/worker — этот module даёт locality и leverage обоим callers.

Типы ниже принадлежат `internal/domain/file_inputs.go`; только adapter знает protobuf, только repository знает SQL. Значение SHA — `sha256:` + 64 lowercase hex, проверяется на входе. Все floating options конечны, отсутствие/null различаются типами, int64 IDs никогда не проходят float64/JSON number в JS.

Q1 будет использовать тот же строгий seam, а не legacy Upload.

### Нормализация до сохранения

Reader для телеметрии **новый**, существующий `spreadsheet.ReadWells` читает каталог скважин и не подходит. Переиспользуем pinned excelize `v2.10.1`, `encoding/csv`, `domain.Mapping` и shared scalar logic `cleanTelemetryScalar`/legacy `cleanValue`. Saved path имеет direct bounded CSV loop; legacy MapTelemetry/telemetryCSV API не переписаны. Принятый `adapter/fileinput.Reader` возвращает typed bounded string rows без сетевых вызовов и не вызывает ingest/CommitTelemetry. JSON maps допустимы только внутри внешнего row adapter; выходные identity/entities типизированы.

Сервер читает schema resource из `pulse-model/esp/params/large.json` через read-only `parameterfile.TelemetrySchemaReader`, снимает bytes/hash/alias map до нормализации. Existing `parameters.local.json` — справочник подписей, без authoritative is_set; его нельзя использовать как единственное доказательство sensor semantics. Перед deployment Q1 schema доставляется как versioned read-only resource из model release, без импорта model в Go и без ручной второй редактируемой копии. Q0 fixture использует маленькую синтетическую params schema. Выбранные mappings полностью сохраняются: source column, canonical, unit, scale/offset, channel-specific missing markers, `is_set` из серверной schema; клиент не может превратить setpoint в sensor. Неизвестный target/дубли canonical/нечисловое значение в mapped channel →422. Неиспользуемые raw columns явно перечисляются в mapping summary, не выводятся в logs. `qg/qg_tex/qn` разрешены отдельным numeric supplement; день берётся из timestamp. Отдельная `dat_zam` mapping пока unsupported, не молча подменяется.

До `MapTelemetry` reader строго валидирует все well ID каждой исходной строки, включая строку с плохим временем: отсутствие WellColumn означает ровно selected Pulse ID; присутствующая колонка должна целиком разрешиться в ту же одну скважину через server catalog и выбранный explicit identity kind. ID строка/int64 exact; неоднозначный mapping или вторая скважина →422/404 без чтения чужого результата. Не подставлять unitek ID в Pulse route. Проверка всех IDs выполняется **до** отбрасывания invalid rows.

CSV: streaming Reader, explicit delimiter, optional UTF-8 BOM, без auto-sniff; все поля limited, header unique. Время offset-aware нормализуется в UTC, naive читается только по explicit layout+timezone; неоднозначные/несуществующие DST timestamps отклоняются, не угадываются. XLSX: explicit worksheet, raw cell values, date1900/1904 учитываются и входят в recipe; формулы в mapped/time/ID cells запрещены, cached values формулы не authority. Не исполнять macros/formulas/external links. XLS/XLSM/Parquet и multiwell — отдельный workflow.

Legacy `MapTelemetryAt(records, source, validationAsOf)` хранит существующий future guard; старый `MapTelemetry` делегирует с `time.Now()`. Saved compact normalization сохраняет тот же validationAsOf/`CapturedAt` semantics, проверяет все ID, затем timestamp/scalars и сортирует только row-index/time refs; `[]map[string]any` и Measurement value maps больше не материализуются для saved файла. Отказ любой mapped/time/ID строки в новом saved flow отклоняет файл целиком; fail-soft старого ingest остаётся прежним. Sorted timestamp ascending, duplicate timestamps →422; no resampling/aggregation в Q0. `cleanValue` удаляет channel-specific 9999/999.9 **до** scale/aggregation; валидный ноль не missing. Попытка mapping объявить 0 missing для F_out/токов/дебита запрещается. Setpoints сохраняются в raw+spec, исключаются из canonical sensors.

`writeTelemetryCSV(io.Writer, data)`/legacy wrapper возвращают прежние bytes для старого пути. Принятый saved `normalizeRows(..., output io.Writer) (int, []string, error)` пишет отсортированные исходные строки через reusable CSV string row непосредственно в bounded writer. Нет целой float matrix, all-row generic records/Measurement maps или retained per-cell pointers. Write/Flush errors и canonical_limit не дают принять частичный output. Canonical wire: UTF-8 RFC4180, LF, header `timestamp` + sorted canonical columns, UTC RFC3339Nano, float64 shortest round-trip, missing empty, finite numbers only. Дата qg — timestamp day. Strict Python reader не выполняет alias remap, timezone guess, aggregation или новый source read. Feature pipeline сохраняет существующую hygiene/ffill/decision/imputation, ни template markers, ни setpoints не становятся measurements.

Это выбранные архитектором обратимые пределы тестового профиля, не согласованная политика реальных файлов и не изменение старого Upload.

|---|---|
| raw / rows / canonical | 20 MiB / 100000 data rows / 50 MiB; чтение `limit+1`, early reject; raw file bytes, не размер multipart envelope |
| columns / mappings / field | 128 raw columns, 64 sensor+supplement targets, 64 KiB decoded cell/CSV field, 64 KiB spec; header row ≤100 |
| XLSX | ZIP expanded total ≤100 MiB, ≤512 entries, any entry ≤50 MiB, ratio expanded/raw ≤100; проверять реально прочитанные распакованные bytes, не доверять только ZIP declared sizes; worksheet XML ≤50 MiB; selected sheet rows/columns limited при iteration |
| excelize | `UnzipSizeLimit=100 MiB`, `UnzipXMLSizeLimit=8 MiB`, private temp dir; Close+remove temp. Это spill threshold, **не общий RSS cap**. ZIP precheck перед OpenReader; workbook-wide expanded budget включает shared strings |

Результат имеет отдельный bound до protobuf/JSON allocation; длинный pathological timeline → `result_too_large`, не silent truncate. Максимальный timestamp span нового recipe ≤366 days ограничивает число окон; прежнее правило min30days сохраняется для `legacy_file_upload_v1`, но нормальность определяется running windows/каналами, не обещанием «30/60 достаточно». Все caps включены в versioned parser recipe; тесты могут уменьшать cap injection, чтобы доказать guards без файлов по100 MiB.

Q0-P ещё должен на максимальном/типичном synthetic workload до Q1 enable измерить parse/inference wall time, Go/Python peak RSS, temp bytes, PG relation+TOAST/WAL growth и latency concurrent status/list; cap limits сами не доказывают memory budget. Тестовый operator останавливает pilot при RSS>1 GiB для Go parser или >2 GiB для ML и temp>128 MiB; это stop budgets, не обещание памяти под max input. ## Identity, actor и idempotency

**Request key** — operation identity, 16–80 ASCII `[A-Za-z0-9_-]`, caller сохраняет через retry/reconnect. `http_request_id` — новый diagnostic attempt, не substitute. Unique namespace `(actor_account_id, operation_kind='file_check', request_key)`, поэтому key reuse на другой Pulse ID тоже конфликтует; разные пользователи изолированы. Actor получают только из `domain.CurrentPrincipal(ctx)` с `Mechanism=session`, active current account, role technologist/admin; new saved path отвергает absent/shared/legacy principal. Старые sync profiles остаются прежними. В тесте actor устанавливается реальным login/session middleware, не полем synthetic body.

Оба digest вычисляет Go на exact stored canonical JSON identity bytes, `encoding/json` typed structs, stable mapping sort, finite numbers, explicit version; исходное canonical JSON byte representation сохраняется рядом с JSONB. JSONB reserialization не используется для пересчёта hashes. Python не переопределяет fingerprint, только проверяет канонические input SHA и свои execution claims.

- `request_commitment_sha256 = H(version, actor_account_id, PulseWellID, raw_sha256, normalized client parse options)`; опции включают все mapping/timezone/layout/sheet/ID kind. Opaque name файла вне identity; format определяется утверждённым spec+bytes, не произвольным extension.
- `fingerprint_sha256 = H(version, request_commitment_sha256, canonical_sha256, parse_recipe_sha256, schema_sha256, resolved mappings, source_kind, PulseWellID, execution_pin, lengths/counts)`; exact raw/canonical stored, recipe содержит server code/resources/config hash. Capture timestamp хранится как часть normalization evidence. Временный trace/span/имя actor/текущая role revision не входят в fingerprint.

Сначала current authorization, затем lookup namespace. Existing accepted input: hash bounded raw+normalized client options → тот же commitment возвращает существующий объект/сохранённый result, без новой канонизации, ML или замены ожидания на текущий default. Изменённый commitment →409. Если для первого acceptance ещё нет объекта — подготовить canonical, выбранный server pin, full fingerprint; atomic insert под unique key сравнивает commitment/fingerprint. Loser race получает ровно winner, если совпадает; иной fingerprint →409. Изменение default bundle/recipe между такими конкурентными первыми запросами считается конфликтом, не «latest wins». Старый key после terminal failure не запускает новую попытку с новым bundle: новый key обязателен. Blob не открывается на list/status/duplicate lookup.

Scope перепроверяется на prepare/accept/open/result read/retry и непосредственно перед compute. Worker Q1 заново читает active account/current role+scope и FundScope, не использует старый session cookie или сохранённые claims как capability. Истёкший browser session не отменяет уже принятое намерение, но inactive/role revoked/scope revoked/archived target останавливает новые исполнения с safe reason; Q1 commit требует повторного scope/fence check, чтобы не записать success после revoke. IDs/result/list не раскрывают чужую скважину. Archived/inactive новой file-check целью не становятся.
