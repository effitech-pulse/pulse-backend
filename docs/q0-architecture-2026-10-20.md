# Q0 — неизменяемый вход и pinning до вычисления · 20.10.2026

Статус: архитектурный handoff для preflight; Q0-1…4 ещё не реализованы и не приняты. Редактируемые C4 current/proposed: [q0-artifact-pinning.drawio](q0-artifact-pinning.drawio). Источник: [требования O2/Q0](o2-q0-execution-2026-10-20.md), [roadmap Q0/Q1/F2 и D1–D4](functional-roadmap-2026-10-20.md). O1/F1 приняты; повторный аудит не выполняется.

## Решение

Добавить bounded file reader к существующему Go MapTelemetry/cleanValue → telemetryCSV и Python bundle-only Upload, сохранив старый sync путь. Q0 вводит bounded raw+canonical snapshot в PostgreSQL, явную типизированную ожидаемую identity и отдельный строгий UploadPinned. В Q1 этот snapshot записывается одной транзакцией с job/outbox. Q0 proof доказывает повторное чтение после рестарта, но не является долговечным worker или очередью.

До первого построения признаков ML разрешает ожидаемый digest в локальном immutable registry, проверяет файлы, runtime/recipe и реальное decision_rule(context, "upload"); при несовпадении отказывает. Нет fallback на ML_MODEL_NAME/latest. Реальные частные файлы остаются за отдельным policy gate; synthetic proof разрешён сейчас.

## Подтверждённый поток и щели

- `internal/transport/httpapi/checks.go` → `service/checks.go:Create` → `Integrations.ReadApp` → `telemetryCSV` → `grpcml.Upload`. `manual_check` сохраняет hash и result после inference; raw/canonical input отсутствуют. Повтор сверяет только период, параллельные запросы могут выполнить ML дважды.
- `/api/v1/ml/upload` → `httpapi/ml.go` → `service/ml.go` → `grpcml/client.go` → `server.py:Upload` → `engine.ml_upload`. Старый streaming wire содержит filename/content, не expected identity. Body ограничен 64 MiB, raw 50 MiB, chunk 1 MiB; response остаётся 200.
- `engine.get_upload_context` выбирает `ML_MODEL_NAME` и mutable `ML_DATA_ROOT/models/<name>`, key cache — name/path/current digest. `load_bundle_context` → `load_versioned_model` → `esp.models.registry.load_model`: meta/model + optional calibrator/drift/normalizer. Проверки before/after load обнаруживают изменение, но не выбирают ожидаемую сохранённую версию.
- `ml_upload.score_telemetry` вычисляет `decision_rule` до features, но не сравнивает с ожиданием. `result_provenance` считает recipe/runtime/source после inference. Source digest покрывает только *.py и не покрывает params JSON; новый recipe обязан покрыть фактически используемые resources/config.
- `Score/get_context` читает research cache/manifest/PG и не участвует в Q0. Data не вызывается для saved file; frontend preview не authority. Landing не участвует. Shared proto/generated — только pulse-contracts.

## Модуль и интерфейс Q0

**Stored file check** — глубокий module: bounds, normalization, identity, storage и replay сосредоточены за небольшим interface; caller не собирает hashes или actor вручную. Seam существующего `TelemetryScorer.Upload` оставляем для legacy. Новый seam `PinnedTelemetryScorer.UploadPinned` передаёт ожидаемую identity и canonical bytes; adapter gRPC — один production adapter, тестовый in-process gRPC server — второй реальный способ проверки transport seam. Не вводим общий plugin/storage platform: PostgreSQL — единственный выбранный production adapter. Deletion test: удаление Stored file check вернёт квоты, hashing, scope и immutable replay в HTTP/worker — этот module даёт locality и leverage обоим callers.

Типы ниже принадлежат `internal/domain/file_inputs.go`; только adapter знает protobuf, только repository знает SQL. Значение SHA — `sha256:` + 64 lowercase hex, проверяется на входе. Все floating options конечны, отсутствие/null различаются типами, int64 IDs никогда не проходят float64/JSON number в JS.

| Тип | Точные поля / смысл |
|---|---|
| `FileParseSpec` | `Version="file_input_v1"`, `Format=csv|xlsx`, UTF-8 CSV `Delimiter` из `,;\t`, `Sheet` для XLSX, `HeaderRow` (1..100), `TimeColumn`, `TimestampLayout` из server allowlist, `Timezone` IANA, `WellColumn *string`, `WellIdentity=pulse|unitek|armits` если задан WellColumn, `Mappings []domain.Mapping` с уникальными source/target. `SchemaSHA256` и разрешённые canonical mappings назначает сервер. |
| `ExecutionPin` | `Version="upload_pin_v1"`, `ModelName`, `BundleSHA256`, `ContextVersion`, полный `DecisionRule` включая `RuleSHA256`, `FeatureRecipeSHA256`, `FeatureSchemaSHA256`, `SourceManifestSHA256`, `RuntimeManifestSHA256`. Не содержит private paths. |
| `PreparedFileInput` | `ID` random UUID/opaque128, `PulseWellID int64`, `ActorAccountID int64`, `SourceKind="uploaded_file"`, `CapturedAt UTC`, `Raw []byte`, `Canonical []byte`, `RawSHA256`, `CanonicalSHA256`, `ParseSpec`, `ParseRecipeSHA256`, `ExecutionPin`, `RequestCommitmentSHA256`, `FingerprintSHA256`, rows/columns/byte lengths. Actor snapshot(role/name/revision) — audit metadata, не основание будущих прав. |
| `FileInputSummary` | ID, Pulse ID, actor ID (только разрешённому caller), created_at, sizes/rows, fingerprints, safe execution identity; payload отсутствует. `StoredFileResult` — immutable typed `UploadResult`, input ID, execution pin, computed_at; наличие результата не называется job status. |

Конкретные service interfaces (context первым):

```go
// Raw bounded reader входит в application module; actor отсутствует в input DTO.
PrepareFileInput(ctx context.Context, wellID int64, key string,
    spec domain.FileParseSpec, raw io.Reader) (domain.PreparedFileInput, error)
AcceptFileInput(ctx context.Context, input domain.PreparedFileInput) (domain.FileInputSummary, error)
ComputeStoredInput(ctx context.Context, inputID string) (domain.StoredFileResult, error)
// CommitStoredResult используется Q0 proof; Q1 пишет result + job state с fence одним tx.
CommitStoredResult(ctx context.Context, result domain.StoredFileResult) (domain.StoredFileResult, error)
UploadPinned(ctx context.Context, pin domain.ExecutionPin,
    input domain.PinnedInputIdentity, canonical io.Reader) (domain.UploadResult, error)
```

`PrepareFileInput` — метод `FileChecks`, получает `scope FundScope`, authoritative current accounts reader, bounded row reader, schema snapshot и операторский `ExecutionPin` в constructor. `AcceptFileInput`/`CommitStoredResult` — repository interface этого module; тело `PreparedFileInput` не декодируется из HTTP JSON. Payload read — отдельный repository метод `StoredFileInput(ctx,id)`, доступный только execution path. Q0 proof вызывает реальные service/repository/gRPC adapters; Q1 worker повторно использует `ComputeStoredInput`, а не legacy `Upload`.

### Нормализация до сохранения

Reader для телеметрии **новый**, существующий `spreadsheet.ReadWells` читает каталог скважин и не подходит. Переиспользуем pinned excelize `v2.10.1`, `encoding/csv`, существующие `domain.Mapping`, `MapTelemetry/cleanValue`, `telemetryCSV`. Новый `adapter/fileinput.Reader` возвращает bounded records без сетевых вызовов и не вызывает ingest/CommitTelemetry. JSON maps допустимы только внутри внешнего row adapter; выходные identity/entities типизированы.

Сервер читает schema resource из `pulse-model/esp/params/large.json` через read-only `parameterfile.TelemetrySchemaReader`, снимает bytes/hash/alias map до нормализации. Existing `parameters.local.json` — справочник подписей, без authoritative is_set; его нельзя использовать как единственное доказательство sensor semantics. Перед deployment Q1 schema доставляется как versioned read-only resource из model release, без импорта model в Go и без ручной второй редактируемой копии. Q0 fixture использует маленькую синтетическую params schema. Выбранные mappings полностью сохраняются: source column, canonical, unit, scale/offset, channel-specific missing markers, `is_set` из серверной schema; клиент не может превратить setpoint в sensor. Неизвестный target/дубли canonical/нечисловое значение в mapped channel →422. Неиспользуемые raw columns явно перечисляются в mapping summary, не выводятся в logs. `qg/qg_tex/qn` разрешены отдельным numeric supplement; день берётся из timestamp. Отдельная `dat_zam` mapping пока unsupported, не молча подменяется.

До `MapTelemetry` reader строго валидирует все well ID каждой исходной строки, включая строку с плохим временем: отсутствие WellColumn означает ровно selected Pulse ID; присутствующая колонка должна целиком разрешиться в ту же одну скважину через server catalog и выбранный explicit identity kind. ID строка/int64 exact; неоднозначный mapping или вторая скважина →422/404 без чтения чужого результата. Не подставлять unitek ID в Pulse route. Проверка всех IDs выполняется **до** отбрасывания invalid rows.

CSV: streaming Reader, explicit delimiter, optional UTF-8 BOM, без auto-sniff; все поля limited, header unique. Время offset-aware нормализуется в UTC, naive читается только по explicit layout+timezone; неоднозначные/несуществующие DST timestamps отклоняются, не угадываются. XLSX: explicit worksheet, raw cell values, date1900/1904 учитываются и входят в recipe; формулы в mapped/time/ID cells запрещены, cached values формулы не authority. Не исполнять macros/formulas/external links. XLS/XLSM/Parquet и multiwell — отдельный workflow.

Маленький совместимый refactor: `MapTelemetryAt(records, source, validationAsOf)` хранит существующий future guard; старый `MapTelemetry` делегирует с `time.Now()`. Saved normalization использует сохранённый `CapturedAt`, не новый wall clock. Отказ любой mapped/time/ID строки в новом saved flow отклоняет файл целиком; fail-soft старого ingest остаётся прежним. Sorted timestamp ascending, duplicate timestamps →422; no resampling/aggregation в Q0. `cleanValue` удаляет channel-specific 9999/999.9 **до** scale/aggregation; валидный ноль не missing. Попытка mapping объявить 0 missing для F_out/токов/дебита запрещается. Setpoints сохраняются в raw+spec, исключаются из canonical sensors.

`writeTelemetryCSV(io.Writer, data)` — извлечённое общее тело существующего serializer; legacy wrapper возвращает прежнюю строку. Bounded writer saved path останавливается на canonical limit, а не после огромного allocation. Canonical wire: UTF-8 RFC4180, LF, header `timestamp` + sorted canonical columns, UTC RFC3339Nano, float64 shortest round-trip, missing empty, finite numbers only. Дата qg — timestamp day. Strict Python reader не выполняет alias remap, timezone guess, aggregation или новый source read. Feature pipeline сохраняет существующую hygiene/ffill/decision/imputation, ни template markers, ни setpoints не становятся measurements.

### Bounded engineering defaults для synthetic pilot

Это выбранные архитектором обратимые пределы тестового профиля, не согласованная политика реальных файлов и не изменение старого Upload.

| Ресурс | Q0 synthetic cap / поведение |
|---|---|
| raw / rows / canonical | 20 MiB / 100000 data rows / 50 MiB; чтение `limit+1`, early reject; raw file bytes, не размер multipart envelope |
| columns / mappings / field | 128 raw columns, 64 sensor+supplement targets, 64 KiB decoded cell/CSV field, 64 KiB spec; header row ≤100 |
| XLSX | ZIP expanded total ≤100 MiB, ≤512 entries, any entry ≤50 MiB, ratio expanded/raw ≤100; проверять реально прочитанные распакованные bytes, не доверять только ZIP declared sizes; worksheet XML ≤50 MiB; selected sheet rows/columns limited при iteration |
| excelize | `UnzipSizeLimit=100 MiB`, `UnzipXMLSizeLimit=8 MiB`, private temp dir; Close+remove temp. Это spill threshold, **не общий RSS cap**. ZIP precheck перед OpenReader; workbook-wide expanded budget включает shared strings |
| acceptance | normalization concurrency1, no unbounded waiting queue; занятый slot →429. parse timeout30s проверяется между records; library call не обещает мгновенной отмены |
| PG logical quota | 256 MiB total retained raw+canonical + spec bytes, max16 inputs, per-account128 MiB, metadata/result cap2 MiB/result; test profile only. Счётчики под row lock в той же tx, включая duplicate races |
| execution | concurrency1; RPC ≤5min как существующий check; file ≤50 MiB/chunk≤1 MiB; transient retry автоматом в Q0 отсутствует |

Результат имеет отдельный bound до protobuf/JSON allocation; длинный pathological timeline → `result_too_large`, не silent truncate. Максимальный timestamp span нового recipe ≤366 days ограничивает число окон; прежнее правило min30days сохраняется для `legacy_file_upload_v1`, но нормальность определяется running windows/каналами, не обещанием «30/60 достаточно». Все caps включены в versioned parser recipe; тесты могут уменьшать cap injection, чтобы доказать guards без файлов по100 MiB.

На максимальном/типичном synthetic workload до Q1 enable измерить parse/inference wall time, Go/Python peak RSS, temp bytes, PG relation+TOAST/WAL growth и latency concurrent status/list; cap limits сами не доказывают memory budget. Тестовый operator останавливает pilot при RSS>1 GiB для Go parser или >2 GiB для ML и temp>128 MiB; это stop budgets, не обещание памяти под max input. Если max-cap не укладывается — уменьшить caps/version или изолировать normalization subprocess, не ослаблять проверки. Измерение научных/приватных данных и большой ML run не входят в Q0.

## Identity, actor и idempotency

**Request key** — operation identity, 16–80 ASCII `[A-Za-z0-9_-]`, caller сохраняет через retry/reconnect. `http_request_id` — новый diagnostic attempt, не substitute. Unique namespace `(actor_account_id, operation_kind='file_check', request_key)`, поэтому key reuse на другой Pulse ID тоже конфликтует; разные пользователи изолированы. Actor получают только из `domain.CurrentPrincipal(ctx)` с `Mechanism=session`, active current account, role technologist/admin; new saved path отвергает absent/shared/legacy principal. Старые sync profiles остаются прежними. В тесте actor устанавливается реальным login/session middleware, не полем synthetic body.

Оба digest вычисляет Go на exact stored canonical JSON identity bytes, `encoding/json` typed structs, stable mapping sort, finite numbers, explicit version; исходное canonical JSON byte representation сохраняется рядом с JSONB. JSONB reserialization не используется для пересчёта hashes. Python не переопределяет fingerprint, только проверяет канонические input SHA и свои execution claims.

- `request_commitment_sha256 = H(version, actor_account_id, PulseWellID, source_kind, raw_sha256, normalized client parse options)`; опции включают все mapping/timezone/layout/sheet/ID kind. Opaque name файла вне identity; format определяется утверждённым spec+bytes, не произвольным extension.
- `fingerprint_sha256 = H(version, request_commitment_sha256, canonical_sha256, parse_recipe_sha256, schema_sha256, resolved mappings, source_kind, PulseWellID, execution_pin)`; exact raw/canonical stored, recipe содержит server code/resources/config hash. Capture timestamp хранится как часть normalization evidence. Временный trace/span/имя actor/текущая role revision не входят в fingerprint.

Сначала current authorization, затем lookup namespace. Existing accepted input: hash bounded raw+normalized client options → тот же commitment возвращает существующий объект/сохранённый result, без новой канонизации, ML или замены ожидания на текущий default. Изменённый commitment →409. Если для первого acceptance ещё нет объекта — подготовить canonical, выбранный server pin, full fingerprint; atomic insert под unique key сравнивает commitment/fingerprint. Loser race получает ровно winner, если совпадает; иной fingerprint →409. Изменение default bundle/recipe между такими конкурентными первыми запросами считается конфликтом, не «latest wins». Старый key после terminal failure не запускает новую попытку с новым bundle: новый key обязателен. Blob не открывается на list/status/duplicate lookup.

Scope перепроверяется на prepare/accept/open/result read/retry и непосредственно перед compute. Worker Q1 заново читает active account/current role+scope и FundScope, не использует старый session cookie или сохранённые claims как capability. Истёкший browser session не отменяет уже принятое намерение, но inactive/role revoked/scope revoked/archived target останавливает новые исполнения с safe reason; Q1 commit требует повторного scope/fence check, чтобы не записать success после revoke. IDs/result/list не раскрывают чужую скважину. Archived/inactive новой file-check целью не становятся.

## PostgreSQL и композиция с Q1

Новая additive migration `internal/migrations/file_inputs.sql`, **version12**, в `migrate.go` после run_scope. Если другой owner уже выделил12, координатор сериализует номер до source writes; в переданной базе CurrentVersion=11. Q0 не меняет manual_check и исторические строки не backfill.

| Таблица | Колонки / constraints / индексы |
|---|---|
| `file_input` | opaque text PK, well_id bigint FK well ON DELETE RESTRICT, actor_account_id bigint FK auth_user ON DELETE RESTRICT, operation_kind, request_key, source_kind, created_at, captured_at, request_commitment_sha256, fingerprint_sha256, raw_sha256, canonical_sha256, parser/schema/execution digests, parse_spec jsonb, parse_identity_bytes bytea≤64KiB, execution_pin jsonb, lengths/counts; finite enum/range/version/hash format checks; UNIQUE(actor_account_id,operation_kind,request_key); INDEX(well_id,created_at DESC,id DESC), INDEX(actor_account_id,created_at DESC,id DESC) |
| `file_input_payload` | input_id PK/FK RESTRICT, raw_bytes bytea≤20MiB, canonical_bytes bytea≤50MiB; declared lengths сверяются application+DDL octet_length; rows/columns guards metadata. SELECT projection payload только execute |
| `file_input_budget` | ключ global/account, retained_bytes bigint≥0, retained_count≥0; fixed lock order global→account; лимит check+increment в acceptance tx, exact duplicate не списывает второй раз |
| `file_check_result` | input_id PK/FK RESTRICT, fingerprint_sha256, execution_pin jsonb, computed_at, result jsonb (typed at application boundary, ≤2MiB); no UPDATE/overwrite. Q1 добавляет unique job_id/FK без переписывания result |

Immutable input metadata/payload и results защищены repository insert-only surface и DDL trigger от UPDATE/DELETE в Q0; test harness удаляет **свою временную schema**, не строки реального store. Trigger не защита от DB owner: текущий trust — доверенный оператор/migration owner. Перед реальным enable least-privilege runtime role SELECT/INSERT и operator backup/access policy обязательны. Digest проверяется при каждом open до передачи bytes в ML; corruption/missing payload → явный `input_corrupt`/`input_unavailable`, без восстановления из archives/livefile. No pgcrypto extension: hashing в Go/Python, SQL values Squirrel placeholders. Bytea поддерживает raw bytes ([PG16](https://www.postgresql.org/docs/16/datatype-binary.html)); storage/WAL/backup overhead измеряется отдельно, logical quota не disk quota.

Q0 repository открывает одну tx для metadata+payload+quota; crash до commit не оставляет принятого input, crash после commit позволяет прочитать те же bytes. `CommitStoredResult` делает insert-if-absent по input_id, проверяет fingerprint, не заменяет прежний result; до result commit compute может повториться. Это **не** background job acceptance/automatic recovery/exactly-once compute.

Q1 получает package-private helpers `insertFileInputTx(ctx,tx,input)` и `insertFileResultTx(ctx,tx,result)`: public repository `AcceptFileJob(ctx,prepared)` начинает tx, блокирует budget/idempotency, вставляет input+payload+job+outbox и commit; только затем HTTP202. Не вызывать `AcceptFileInput` с отдельным commit перед job/outbox. Broker получает opaque job/event/input refs, не payload. Success transaction проверяет current lease/fence/cancel/authorization, вставляет result и terminal job state атомарно. Snapshot ID — FK в job. Дубли transport и restart читают этот snapshot. Q1 собственные migration/worker/retry/DLQ планируются отдельным контрактом; Q0 не добавляет брокер.

## Strict pinning: actual bytes и actual policy до features

Новый `pulse_ml/pinned_upload.py` предоставляет `load_pinned_context(pin: ExecutionPin) -> PinnedUploadContext`, `ml_upload_pinned(content: bytes, identity: PinnedInputIdentity, pin: ExecutionPin) -> dict`. Последовательность обязательна и тестируется spy-счётчиками feature/predict calls:

1. Проверить mandatory complete header, supported pin version/context/operation, форматы digests, declared canonical size; bounded streaming content hash совпадает с canonical SHA. Нельзя считать header blob path/имя произвольным filesystem path.
2. Resolve `ML_BUNDLE_REGISTRY/<64hex>/` — выделенный registry root, иной чем mutable `/data/models`. Backend принимает только operator-allowlisted pin; сеть/брокер/браузер не могут загрузить pickle или новый model. Root trusted, no symlink/traversal, model_file — basename из allowlist .cbm/.pkl, полный required file list + explicit optional absence из manifest. Unknown/external model_file/extra executable resource → reject.
3. Registry создаётся operator command `python -m pulse_ml.bundle_registry import --source <trusted-local> --registry <separate-root>`: hash/validate file set, copy в private staging, проверка hashes после copy, manifest, fsync файлов+каталога, atomic no-replace rename в digest directory. No hardlinks/symlinks; существующий digest directory не overwrite. Import не promotion и не принимает HTTP uploads. Q0 test импортирует только synthetic bundle в temp; реальный legacy импорт/новый mount — отдельное контролируемое действие при enable. ### Межрепозиторный typed wire

Новый метод в **pulse-contracts**: `rpc UploadPinned(stream PinnedUploadChunk) returns (UploadResponse)` в текущем v1 namespace, additive. Отдельный метод обязателен: добавленный optional header к старому Upload старый server мог бы проигнорировать и вычислить latest. Старый server на неизвестный RPC отвечает UNIMPLEMENTED; Go считает это `pinned_protocol_unavailable` без downgrade.

Новые messages: `ExecutionPin` с полями таблицы выше (DecisionRule typed); `PinnedInputIdentity{input_snapshot_id, canonical_sha256, fingerprint_sha256, canonical_bytes:int64, source_kind}`; `PinnedUploadHeader{pin,input}`; `PinnedUploadChunk{oneof payload {header; bytes content}}`. Первый chunk **только header**, далее только bytes≤1MiB, repeated/missing header/empty pin →INVALID_ARGUMENT, raw user filename/path не требуется. Canonical total≤50MiB. Existing UploadChunk/UploadResponse/provenance optional поля и номера не переиспользовать. В response уже есть input_snapshot_id; semantic value input_sha256 в новом RPC = canonical bytes, в старом Upload = его raw transmitted file. Spec явно различает эти cases. Actual error codes: invalid/header/input hash→INVALID_ARGUMENT; unavailable/corrupt bundle→FAILED_PRECONDITION; expectation mismatch/unsupported recipe→FAILED_PRECONDITION; bound→RESOURCE_EXHAUSTED. Sanitized finite reason codes без путей/данных; Go rpcError маппится на domain invalid/unavailable/limited с safe typed code. В O1 interceptor allowlist добавить только новый known method/statuses, не metadata labels.

Новые поля исключительно с новыми номерами; Buf lint/breaking против baseline contracts SHA выше, Go/Python round-trip с int64>2^53, absent/false/zero/null. Patch/minor release по существующему release policy (additive capability требует следующей согласованной версии обоих SDK); версия исходного worktree не называется опубликованной. Обновление consumer go.mod/go.sum/pyproject и generated SDK только после contracts frozen diff, root контролирует release/publication gate. Никакого локального proto в backend/ML. Исторический DOC-04 разрешал только спецификацию. Следующий source handoff координатора должен явно включить Q0-C additive contract и зафиксированный baseline в уже одобренном продолжении; это конкретный scope check перед edit, не новый общий запрос разрешения пользователю. JSON/reflection обход запрещён.
