# Модель и причинная валидация

## Текущий исполняемый комплект

Локальный `stage1_binary_v1` — исследовательская бинарная CatBoost-модель. Проверка файла строит окна 48 часов с шагом 12 часов; минимальная история — 30 суток. Она возвращает norm/watch/alert/insufficient, timeline, числа доступных/недоступных признаков и объяснение. Это не готовая классификация всех 13 физических причин.

Ручная проверка сохраняет имя, дату и SHA256 комплекта модели, SHA256 CSV-входа, период, число точек и разрешение. Если идентификатор артефакта неизвестен, возвращается null. Не подставляется выдуманная версия.

Contribution содержит value_source: `computed`, `training_median`, `zero_fallback`; у старых результатов источник может быть неизвестен. Заполненный медианой признак не называется измерением датчика. Состав каналов не расширяет автоматически обученный вход модели. `features_unavailable` должен быть виден пользователю.

## Риск и ярус

Риск последнего окна, накопленный ярус и data_ok независимы. Общий typed evaluator применяет явные DecisionRule/policy из согласованного контекста: legacy Score и Upload сохраняют разные шкалы/операторы и K; округлённый display risk не восстанавливает решение. Низкий последний риск или проблема связи не отменяют накопленного яруса. Решение технолога также не меняет его автоматически.

Бинарная модель, калибратор, meta.json и профиль дрейфа передаются согласованным комплектом. Для causal_v1 требуется свой normalizer.pkl. Автоматического выбора latest и продвижения кандидата нет.

## Целевая модель

Проектная архитектура — маршрутизирующий каскад: гигиена данных → детектор аномалии/дрейфа → маршрутизация по динамике → классификация или survival внутри бакета.

| Бакет | Задачи |
|---|---|
| SLOW | Парафин, соль, ВНЭ, износ РК; дни/недели |
| MECHANICAL | Вал, вибрации, засорения |
| FAST | Смена режима, изоляция, сеть/ЧРЭП; секунды/минуты |
| SYSTEM | Потеря связи, frozen-data; детерминированное правило |

В коде присутствуют исследовательские реализации и тесты разных алгоритмов. Их наличие не означает, что весь каскад включён в локальный RPC-сервис и прошёл приёмку. LSTM-AE, survival и тонкая классификация не заявляются действующей промышленной моделью только по архитектурному документу.

## Таксономия отказов

| № | Причина | Основные сигнатуры |
|---|---|---|
| 1 | Парафин НКТ | Рост линейного давления/мощности/температуры, снижение дебита при сопоставимой частоте |
| 2 | Соль в насосе | Падение напора, рост/флуктуации тока и ЗСП |
| 3 | Верхняя утечка НКТ | Падение дебита, рост давления приёма |
| 4 | Нижняя утечка НКТ | Рост затрубного/приёмного давления, ток близок к ХХ |
| 5 | ВНЭ | Падение нагрузки/тока/cos φ, рост давлений и ЗСП |
| 6 | Слом вала | Вибрационный тренд, сильная недогрузка и низкий cos φ |
| 7 | Смена условий | Изменения давления/обводнённости, флуктуации тока/частоты |
| 8 | Засорение насоса | Ток между ХХ и номиналом, флуктуации, рост давления приёма |
| 9 | Засорение приёма | Телеметрически близко к №8 |
| 10 | Износ рабочих колёс | Падение дебита, рост удельной энергии, низкий cos φ |
| 11 | Деградация изоляции | Падение/флуктуации R_izol, дисбаланс токов |
| 12 | ЧРЭП/сеть/перегрев СУ | Асимметрия фаз, провалы напряжения, нелинейная нагрузка |
| 13 | Потеря связи | Отсутствие новых данных, frozen-data и состояние ТМС |

На старте №2/8/9 объединяются в суперкласс отложений/механического засорения; уверенно разделять их по тем же каналам нельзя. Гигиена и signatures не заменяют диагноз технолога.

## Протокол оценки

Train строго раньше test; группы не пересекаются; purge/embargo удаляют окна у границ. Нормировщик fit только на train, калибратор — calibration, порог — selection. Test используется для отчётности. Контекст соседей и собственной базы строго причинный. SMOTE сырых временных окон запрещён; усложнение принимается только при выигрыше в одинаковом протоколе.

Для текущего причинного бейзлайна используется имеющаяся группировка НГДУ вместо недоступного полного справочника физических месторождений. Это ограничение, а не подтверждённый oilfield split. Скрипт оценки: `pulse-model/scripts/eval_honest.py`.

## Известные результаты

| Проверка | Результат | Интерпретация |
|---|---|---|
| Исторический stratified group-CV | Отдельный старый отчёт | Не подтверждает временную приёмку 7–14 суток |
| Honest baseline, 3 seed × 5 split | Средняя precision ≈7.8%, своевременный recall ≈83.3% | Диагностический бейзлайн; 34 положительных скважины на тестовую когорту seed, девять НГДУ |
| Regime-кандидат | Precision 7.78→7.67%, recall 83.33→79.41% | Критерий улучшения не выполнен; research_rejected |
| Реакция на 100 искусственных скважин, 15 сценариев | В выполненных проверках выявлено 0/15 | Генератор не доказывает работоспособность обнаружения деградации |

Исходные причинные отчёты находятся в репозитории model и workspace-data/reports. Исторический файл с названием acceptance_report содержит более ранние заявления; их нельзя переносить в текущую приёмку без нового временного теста. Отчёты с индивидуальными данными скважин в этот комплект не включаются.

## Воспроизведение и продвижение

Из pulse-model: `make honest-cache`, `make honest-eval`; эксперимент режима — `make regime-cache`, `make regime-eval`. Команды обучают/оценивают модели и требуют подготовленных локальных данных; это не smoke-check веб-приложения.

Перед продвижением: фиксируются данные/код/протокол; проверяются утечки, recall по классам, macro-F1, confusion matrix и заблаговременность; утверждаются пороги и цена ошибок; сохраняется предыдущий комплект. Просмотренный test становится диагностическим и не служит новой независимой приёмкой. Производственная приёмка текущего комплекта ещё не закрыта.


## Поддерживаемые RPC и происхождение результата

[Матрица моделей/RPC](../references/model-rpc-compatibility.md) описывает фактическую шкалу, оператор порога, K/lookback, cold start и границы Score/Upload/History. PREP добавил typed decision/provenance и согласованное evidence History; causal Upload явно отклоняется как unsupported_feature_recipe до feature construction, unknown context — как unsupported_context_version. Provenance envelope реализован, но его статус partial: exact input bytes для replay не сохраняются. Поддержка evaluator не является научной приёмкой causal-кандидата. [Полный причинный бейзлайн](../references/causal-baseline.md) включён как датированный исследовательский источник.

## Пользовательский runtime PREP и scientific gate

Upload загружает только bundle модели с thread-safe cache и проверкой fingerprint на запросе и до/после загрузки. Research Score с manifest/cache/PG не является предварительным условием Upload. Cohort backend строит вход через ReadApp/CSV для каждого из 100 зафиксированных участников, сохраняет `scored`/`archived`/`inactive`/`insufficient`/`error` и null result у неоценённых; риск 0 не используется вместо отсутствующего результата.

Полный stored output, as_of, bundle/policy identity и digest доступны после restart. Это проверка сохранности результата; immutable input bytes не хранятся и provenance partial. TreeSHAP Upload относится к peak raw-score окну; latest risk/date остаются latest. Computed/training_median/zero_fallback и unknown источник объяснения различаются, включая literal 0.

[Независимая приёмка readiness_v1](../references/independent-acceptance.md) и [публичный пример протокола](../examples/readiness-protocol.example.json) определяют закрытый test, physical oilfield mapping, availability, обе популяции во всех ролях и раздельные горизонты 7–14/7–30. Валидатор проверен на fixtures; незаполненный пример должен давать blocked. Software PASS не устанавливает истинность меток/независимость данных и не вычисляет научную приёмку: status scientific_acceptance=not_assessed. Пользователь отложил новые внешние данные и подключение ML; новые метрики и продвижение не выполнялись.
