# O2 — проверка локального контура 20.10.2026

Статус: runtime-проверки O2-1…4 выполнены; финальное Senior-заключение и публикация фиксируются в execution ledger. Это фактические результаты изолированного `pulse-prep`, а не разрешение на production. [Требования](o2-q0-execution.md), [архитектура](o2-architecture.md), [runbook](observability-o2.md). O1/F1 ранее приняты и повторно не открывались; сравнение ниже относится к совместимости O2.

## Выполненные проверки

Четыре образа `:o2` собраны для Linux ARM64; принятые `:o1-f1` сохранены. Новые Python images содержат исправленные модули, проверенные по SHA256, и согласованные зависимости; `pip check` проходит. Source Senior: Go — без замечаний; Python — повторное ревью закрыло два замечания; stack — повторное ревью закрыло блокировку budget-файла, очистку измерителя и проверку целочисленных snapshot. Сетевая поправка Grafana и последующее ограничение Go memory прошли независимое source-ревью; итоговая whole-wave проверка учитывает оба delta.

Реальный workload использовал синтетическую скважину1004, положительный CSV за65суток и существующий доверенный комплект модели. Создание проверки, сохранённый результат, повтор с тем же ключом, чтение, конфликт периода409 и запрет записи viewer403 прошли на O1, на O2 с выключенным экспортом, с включённым экспортом и при отказах. Первая включённая проверка сохранила1537точек с verdict `norm`; это проверка пути исполнения, не оценка качества ML. Отдельная интеграция скважины1005 фактически вызвала Data и записала наблюдения в PostgreSQL; источник затем приостановлен.

Tempo вернул отдельный `check.execute` root с восемью spans: Backend, чтение телеметрии, обращение к Data, ML Upload и сохранение результата. Его link указывает на исходный HTTP span; Data HTTP и ML RPC имеют реальные родительские spans. Отдельный сбор через Data дал пять spans. Логи найдены по ID попытки через `| json | http_request_id = "…"`. Detached root не следует искать исключительно по HTTP trace ID.

Каждый из пяти компонентов — Collector, Loki, Tempo, Prometheus, Grafana — отдельно останавливали на20секунд и запускали вновь. Во всех пяти случаях положительная проверка и остальные бизнес-проверки прошли. Потери диагностики видны: stdout накопил ошибки экспорта и отброшенные spans, Collector сообщил ошибки отправки в Loki/Tempo. После восстановления Prometheus получил cumulative значения: Backend traces dropped51/export failures26/metric failures5, Data7/6/5, ML3/3/5. Это зарегистрированные потери пилота; lossless доставка не заявляется.

В реальном Prometheus найдены440 `pulse_*` series, включая22 комбинации completion и330 histogram buckets; единицы времени — секунды, heap — bytes. В custom metric labels отсутствуют request/trace/span/well/account IDs; exemplar query пуст. Loki `/series` показал только service/environment index labels для четырёх producers. Structured metadata ответа query_range не является дополнительным индексом. Синтетический canary в query string, baggage, tracestate и User-Agent отсутствовал в найденных логах.

Все проверенные строки stdout трёх приложений — JSON не более8192bytes. Шесть snapshot counters имеют целочисленный неотрицательный тип; наблюдаемые очереди traces не превышали11, logs —0 при лимите256. В ходе пилота зафиксирован общий скачок wall clock Docker VM примерно816.5секунд, поэтому максимум разницы UTC timestamps нельзя выдавать за интервал работы ticker. Отдельный активный25секундный замер по monotonic arrival подтвердил интервалы около10секунд: максимум10.004/10.012/10.004секунды для Backend/ML/Data. Планирование ОС и остановка VM не дают жёсткого realtime SLA.

Grafana внутри telemetry network ответила200 с авторизацией и401 без неё, provisioned три datasource UID. Реальный сервер работает UID472, effective/permitted/inheritable/ambient capabilities равны0, `NoNewPrivs=1`. Пароль отсутствует в прочитанных от UID472 environ/argv и логах. Host UI gate первоначально не прошёл: Docker Desktop не выделил published port для internal-only сети. Пользователь явно разрешил отдельный Grafana-only bridge для локального пилота. Его возможность исходящих соединений документирована; Collector и хранилища остаются internal. Фактический host3300 gate прошёл:401 без авторизации/200 с ней, три datasource UID, sole loopback binding и только Grafana в UI bridge. Через браузер выполнены три прохода login → Loki11строк → derived Pulse Tempo link → check.execute/8spans/3services → Related logs; запросы вернули200 без page errors. Отдельно отображена таблица runtime metrics.

Supervisor на фактическом истечении20секунд остановил ровно пять optional containers, сохранив четыре приложения и PostgreSQL. После остановки новая положительная проверка также прошла. Управляемый откат вернул четыре образа`:o1-f1`; девять результатов из предшествующих фаз повторно получены по прежнему request key и ID с неизменным SHA256 результата. После финального повторного отката проверены уже13phase результатов с прежними ID и SHA256, а также ID восстановленной после ML outage проверки. Store volumes и бизнес-БД сохранены. Общий `down -v` не применялся; исходный контур8080 и живые БД не изменялись.

Отдельная остановка именно ML при работающей диагностике дала503 на валидную проверку. После восстановления ML тот же ключ дал200 и сохранённый результат. Метрики показали error для `check.execute`/`MLService/Upload`, тогда как все шесть Backend exporter-failure series оставались0 и три scrape targets были up. Это ошибка доступности inference-зависимости, а не искусственно вызванное исключение внутри модели.

После перезапуска Collector в первом прогоне обнаружено дублирование:22строки/11distinct тел запроса проверки и12/6 для collection. Checkpoint volume — tmpfs; после потери offsets или неопределённой доставки повторное чтение допустимо. Бизнес-результаты при этом не дублировались.

## Замеры и ограничения

Первый supervised запуск длился около668секунд по monotonic timer; прирост четырёх stores составил около11.8MB, свободное место оставалось выше10GiB. Второй короткий запуск подтвердил автоматическую остановку по сроку. Предел одного запуска —1800секунд с явно ограниченными накладными расходами CLI, измерения и остановки, не жёсткий wall-clock deadline. Последовательные Docker measurement calls могут занять до46секунд, budget lock — до0.5секунды, stop — до25секунд; polling добавляет до5секунд. Физическая disk quota обычных store volumes отсутствует.

В финальном supervised запуске последний успешный замер показал23.05MB stores, прирост11.07MB за≈1087monotonic секунд. Управляемое завершение во время Docker measurement было зарегистрировано как unobservable/creation_completion_unknown; guard остановил пять optional containers. Отсутствие ровно названного helper дополнительно подтверждено lookup; это не гарантия отмены запоздалого daemon RPC. Все три supervisor runs оставались короче1800s с оговорёнными CLI overhead; budget между ними не сбрасывался.

В исходной серии собран181 Docker stats sample. Часть phase labels охватывает также переход/восстановление, поэтому эти samples не используются как точное сравнение overhead. Повторный контролируемый замер собрал160samples с image ID, началом контейнера, producer flag и monotonic time;19 переходных/неподходящих samples исключены из summary. O2-off означает выключенный producer export; часть этого интервала stores уже работали. Для Grafana summary отдельно разделяет epochs до/после memory fix. HTTP latency измеряется отдельно от reserve/release бюджета. Workload мал и последователен; p95 при8–13запросах практически равен максимуму. Холодный/прогретый ML cache и Docker VM влияют на измерение. Вывод о production capacity или ускорении O2 из этих чисел не делается.

Корневая evidence-директория: `/private/tmp/pulse-o2-q0-20261020`; lane snapshots/reviews — собственный `.superpowers/sdd/o2-q0-execution-2026-10-20`. Приватные env/accounts/password files в отчёт и Git не включаются. В общей lease-базе167business HTTP requests, inflight0; предельная concurrency2 соблюдена. Grafana/operator queries и встроенные health probes — диагностическая нагрузка, не business requests. Финальный workload8запросов: p50≈4.18ms, p95≈1.169s (создание ML-проверки); сравнение с холодным baseline не является benchmark.

Из sampled O2 значений: Backend19.28MiB/20.41%CPU/17PIDs, Frontend11.91MiB/1.79%/15, ML133.90MiB/13.26%/56, Data70.11MiB/9.17%/33; Collector104.40MiB/9.63%/9, Loki89.70MiB/16.0%/8, Tempo177.20MiB/14.7%/8, Prometheus43.57MiB/5.05%/7.
