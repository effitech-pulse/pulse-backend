# O1: локальная корреляция и безопасная диагностика

HTTP `X-Request-ID` и gRPC `x-request-id` обозначают попытку выполнения. Они не меняют бизнес-поле `request_id` и не участвуют в idempotency. Единственное допустимое входное значение соответствует `^[A-Za-z0-9_-]{16,64}$`; отсутствующее, множественное или недопустимое заменяется случайными 32 hex-символами. API возвращает ID в заголовке также на ошибках/отказе доступа и предоставляет его браузеру через CORS. Формат тела ответа сохранён.

Поддерживается только W3C `traceparent` (один заголовок, максимум512 bytes, без control chars), проверяемый официальным propagator. Baggage/tracestate не переносятся. Контекст не даёт прав доступа и не заменяет локальную политику sampling. Исходящие gRPC metadata сохраняют действующий `x-ml-api-key` и deadline; metadata не записываются в лог.

`internal/observability` использует OTel API/trace SDK1.38.0. Provider создаётся при старте API до listener/планировщиков, локальный sampler100%, атрибутов32, событий16, ссылок8, строка атрибута≤256. Runtime не содержит exporter, network endpoint, batch queue или списка завершённых spans; test exporter существует только в тестах. Shutdown ограничен2 секундами. Resource содержит только `service.name=pulse-backend`, build/version (сейчас `unknown`), случайный instance ID и `deployment.environment.name=local`.

Важная особенность SDK1.38: даже `WithResource(NewSchemaless(...))` автоматически объединяет `resource.Environment()`. Поэтому конструктор под mutex временно убирает `OTEL_RESOURCE_ATTRIBUTES`/`OTEL_SERVICE_NAME`, создаёт provider и точно восстанавливает присутствие/значения через defer. Ошибка env-операции даёт безопасную ошибку инициализации без значений. **Это startup-only операция:** mutex сериализует собственные конструкторы, но не защищает чужие параллельные чтения process-global env. Повторно инициализировать provider после запуска фоновой работы нельзя. Canary-тест проверяет allowlist resource и восстановление непустых/пустых/отсутствующих переменных.

HTTP SERVER span охватывает auth/recovery/ответ; имя и `http.route` используют шаблон Gin, неизвестный путь — `HTTP unmatched`. ML unary CLIENT span заканчивается после результата. Upload CLIENT span остаётся открытым на всём чтении/передаче и до `CloseAndRecv`, завершается один раз также на read/send/size/cancel/error. Нет span на chunk. Archive и JSON pull создают CLIENT span фактического HTTP-вызова с безопасной передачей контекста. Нет URL/query/external ID в атрибутах. Реальные PostgreSQL операции именуются `telemetry.read`, `telemetry.bounds`, `telemetry.save`, `check.save`; это не driver-level SQL tracing.

Ручная проверка создаёт новый root `check.execute` со ссылкой на HTTP span и сохраняет прежний `WithoutCancel`/права/срок записи. Background ML captures только correlation/SpanContext до goroutine и создаёт связанный root `ml.run`; Gin Context не удерживается. Сбор создаёт `telemetry.collect`; PG-only проверка не создаёт фиктивный Data span.

Каждая запись slog — JSON строка со следующими общими ключами: `timestamp` UTC RFC3339Nano, `severity_text`, статический `event_name`, `service.name`, `service.version`, `service.instance.id`, `deployment.environment.name`. Активный контекст добавляет `trace_id`, `span_id`, `http_request_id`. Числовые поля: `duration_ms`, HTTP/gRPC status. Дополнительные поля ограничены исходным allowlist; единственная форма бизнес-идентичности — 64hex `operation_digest`. DEBUG выключен. Запись≤8192 bytes; большие дополнительные поля отбрасываются до записи валидного JSON.

Ошибки и panic дают только статический `error_code`, без `Error()`, metadata, stack, DSN, SQL params, filename/body, query/path IDs, review/comment и персональных данных. Неизвестные runtime/third-party сообщения становятся `diagnostic.suppressed`, их текст/attrs не форматируются. API также направляет стандартные HTTP/gRPC diagnostics через безопасный slog bridge. Ошибка/паника writer подавляется; результат операции сохраняется. Это не защита от OS-level блокировки stdout и не гарантия lossless/durable logs.

Nginx (`pulse-frontend/nginx.conf`) генерирует новый `$request_id`, пересылает его API, скрывает upstream дубликат и возвращает свой ID `always`, включая локальные ошибки. Access log — JSON с тем же envelope, безопасной группой `/api/*`, `/health`, `/openapi.json` или `spa` и числовыми status/`duration_s` (**секунды**). Nginx не генерирует trace/span ID. Container timezone должна оставаться UTC для `$time_iso8601`. Native request error stream отключён (`error_log /dev/null crit`), поскольку он может содержать URI/upstream details; это осознанное сокращение диагностики. Ошибки launcher/config до загрузки конфига остаются native и не считаются отформатированными O1.

Stdout — единственное назначение. В изолированном Compose профиль координатора задаёт Docker `local`, `max-size=10m`, `max-file=3`; прямой CLI сам не ротирует stdout. Collector/stores, brokers/jobs, schema/proto и scientific acceptance этим этапом не добавлены.

Проверки: `make check`, `make build`, `TEST_DATABASE_URL=<отдельная БД> make integration`. Новые тесты используют настоящий SDK/in-memory exporter, HTTP listener и gRPC bufconn, проверяют parent/link IDs, завершение Upload, приватность и fail-soft sink. PG integration использует отдельную тестовую схему и прежние проверки idempotency/RBAC/disconnect.
