# Пульс скважины — интерфейс

## Портал · 21.10.2026

Актуальный пользовательский runtime — `http://127.0.0.1:8088/`. Обзор, список
и карточка перенесены в первой волне; тревоги, проверка файла, журнал,
интеграции, система и вход — во второй. Журнал сверки Light/Dark Figma, границ API и
проверок сохранён в локальном workspace: `../tasks/pulse-frontend/docs/portal-rest-2026-10-21.md`.

Источник тестовой выборки — **Pulse Connector**. Переключение рабочих/показательных
фондов, отдельный presentation-экран и автономный demo-entrypoint удалены из
рабочего приложения. Сервер возвращает единую разрешённую выборку; клиент не
фильтрует её по историческому `fund_type`. Старые enum в HTTP/исторических данных
сохранены только для совместимости и проверки прав. В существующих аккаунтах
`scope.funds` не расширяется. Сохранённые результаты и ID не мигрируют.


React, Ant Design и Vite. Для общего рабочего режима, включая `npm test`, используйте Node.js 22.18+ (CI использует ветку Node 22).

```sh
npm ci
npm run dev
npm run build
```

Разработка: http://localhost:3000, API проксируется на http://localhost:8000. Для размещения готовой сборки dist/ настройте reverse proxy /api и /health к бэкенду. Локальные файлы телеметрии и веса модели сюда не входят.

## GitHub CI

Workflow `.github/workflows/ci.yml` запускается на push в `main`, pull request, тег `v*` и вручную. Запускает `npm test`, собирает статический сайт в `dist/` и сохраняет артефакт на 30 дней. Развёртывание и загрузка рабочих данных не включены. Секреты для CI не требуются.
## Интеграции и телеметрия

Раздел `/integrations` содержит настройку источников, словарь полей, интервалы
сбора и журнал. Телеметрия встроена во вкладку карточки существующей скважины:
`/wells/{id}?tab=telemetry`. `/telemetry/{ID Pulse}` перенаправляет в
карточку; `/telemetry/demo-001` — в реестр. Генерации данных в браузере нет.

При открытии выбирается последняя доступная история источника, а не пустой
период сегодняшней даты. Режим «Онлайн» сдвигает период к текущему времени.
Обновление интерфейса 5/60/900 секунд настраивается отдельно от сбора источника.
Pulse Data читает реальный архив по связке Unitek/device ID, отдаёт часовую сетку
last-in-bin без заполнения пропусков; разрешение указано возле периода.


Просмотр поддерживает отдельные и совмещённые каналы, относительное изменение
и две оси, сравнение периодов с общими шкалами, синхронным курсором и масштабом,
таблицу с качеством, фильтр пропусков и сохранение выбранного набора каналов.
Импорт Excel/CSV/Parquet проходит предпросмотр и подтверждение; экспорт включает
выбранный интервал и исходные значения. В сравнении добавляется метка периода A/B.
Шрифт Roboto хранится локально, тема сохраняется в браузере без сетевого запроса.

`npm test` (Node 22.18+) проверяет обработку нулей, маркеров, дубликатов, времени,
нормирование и обратное чтение CSV/XLSX/Parquet. `npm run build` проверяет TypeScript
и собирает приложение. Подключение backend описано в соседнем
`pulse-backend/docs/telemetry-integrations.md`; новые API требуют явной миграции.
Для локального API на другом порту можно задать `VITE_API_PROXY_TARGET` при запуске
Vite. Автоматического перехода на демо при ошибке API нет.


В карточке и реестре основным идентификатором является ID Pulse (`well.id`).
Unitek/Armits вынесены в «Интеграции → Связи скважин» и не обязательны для
создания. Сопоставления редактируются отдельно от паспорта скважины.
Просмотр, импорт и экспорт телеметрии используют ID Pulse; backend разрешает
связь с архивом. Экспорт реестра содержит PULSE_ID без внешних ID. Повторный
импорт такого реестра пропускает существующие строки, не меняя ID.
Для источника задаётся тип ID передаваемых скважин; неверное сопоставление
не записывает пакет. Изменения требуют явной миграции 3 backend.

### Сохранённая проверка синтетического файла (Q1/F2)

`/upload-check` запрашивает `/api/v1/file-check-capabilities` для текущего local-сеанса.
Только `enabled=true, mode=synthetic` включает сохранённую проверку CSV/XLSX
(20 МиБ, одна скважина Pulse, 100 000 строк). Сначала указываются точный ID Pulse,
часовой пояс IANA, строка заголовка, формат времени, лист/разделитель и соответствие
каналов. Локальный просмотр показывает первые пять строк и не является результатом ML.
Исходный файл и настройки отправляются серверу; в URL/браузерное хранилище они не пишутся.

202 означает принятие, затем клиент читает состояние. Закрытие браузера и сетевой
таймаут не отменяют принятое задание. Повтор после потери ответа сохраняет request_id;
для изменённого файла/настроек требуется явная новая операция. Отмена отправляется
отдельным действием с текущей revision. Сервер остаётся источником прав и состояния.

В карточке скважины, вкладка «Проверки», истории периода и файлов разделены и имеют
собственные серверные курсоры. `check=q1_<jobID>` читает только dedicated file result/review,
обычный ID — существующую проверку периода. Чтение не запускает ML. Недостаточность
данных сохраняется как отдельное заключение, без нулевого риска. Новые file well ID
передаются десятичной строкой; unsafe int64 ответа сохраняются строками.

При feature off сохраняется прежняя синхронная проверка admin (CSV/XLSX/XLS, 50 МиБ).
Технолог видит доступный по capability сохранённый сценарий; legacy-загрузка ему не
разрешается. Выход, 401 и отказ private scope очищают память черновиков/результатов и
останавливают запросы. Отмена browser-запроса не отменяет server job.

Для изолированного frontend QA можно задать `VITE_API_PROXY_TARGET` и собственный порт:
`VITE_API_PROXY_TARGET=http://127.0.0.1:8021 npm run dev -- --host 127.0.0.1 --port 5179 --strictPort`.
Это не переключает рабочий портал. Backend должен быть отдельно запущен в разрешённом
synthetic-профиле; frontend не включает его и не допускает реальные файлы от имени пилота.
