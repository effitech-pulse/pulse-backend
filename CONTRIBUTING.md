# Разработка

## Каталоги и зависимости

Используем [golang-standards/project-layout](https://github.com/golang-standards/project-layout). Новые исполняемые программы размещаем в `cmd`, приватный код — в `internal`. Не добавляем пустые каталоги шаблона. Публичные gRPC SDK принадлежат `pulse-contracts`.

HTTP-слой использует Gin: `gin.Context`, RouterGroup и middleware. Gin-типы остаются в транспорте; сервисы принимают `context.Context` и доменные типы. Listener и graceful shutdown обслуживает `http.Server`.

HTTP-обработчик декодирует типизированный запрос, вызывает сервис и формирует ответ. Сервис валидирует бизнес-правила и обращается к интерфейсу хранилища. SQL находится в PostgreSQL-адаптере. Конкретные зависимости собираются в `bootstrap`.

Запросы строим через `github.com/Masterminds/squirrel`, выполняем через pgx. Значения передаём параметрами; `sq.Expr` используем для PostgreSQL-функций, casts и вложенных запросов. DDL хранится в миграциях. Нумерация placeholders выполняется один раз после сборки вложенных Sqlizer.

Protobuf SDK генерируется в `pulse-contracts` через Buf и официальные плагины. В gRPC-адаптере используем generated-типы и явное преобразование в domain. Reflection-кодеки и промежуточный JSON не добавляем. Перед изменением схемы выполняем `make lint`, `make breaking` и тесты в репозитории контрактов.

## Go-код

- `gofmt`; импорты группируем: стандартная библиотека, сторонние зависимости, пакеты проекта.
- Имена отражают смысл. Не объединяем независимые поля конфигурации в одной строке.
- Типизированные структуры для сущностей и DTO. `map[string]any` допустим для расширяемых JSON-параметров и на границе внешнего формата.
- `context.Context` передаём первым аргументом. Каналы и соединения закрывает их владелец.
- Ошибки возвращаем с причиной через `%w`/`Unwrap`; наружу не выводим SQL и секреты. Логи — `slog`.
- Null, отсутствие поля и ноль различаем. Для PATCH используем `domain.Field[T]`.
- Generated код руками не правим. Тесты не заменяют проверку API-контракта и миграций.

## Перед изменением

```sh
make fmt
make check
TEST_DATABASE_URL=... make integration
make build
```

В изменениях API сверяем `api/openapi.json` и frontend. Миграции выполняются только явно; старые данные не пересоздаём. Контрактные изменения выпускаем через отдельный репозиторий и обновляем версии обеих зависимостей.
